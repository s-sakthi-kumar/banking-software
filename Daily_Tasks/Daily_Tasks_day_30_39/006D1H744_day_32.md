* Cloud computing is **scalable and pay-as-you-go**, allowing resources to be increased or decreased on demand. Traditional on-premises IT requires **upfront hardware investment** and scaling usually means buying and installing more physical servers.

* Deploying across multiple Availability Zones improves **availability and fault tolerance**. If one AZ fails, the application can continue running in another AZ.

* **Least privilege** means giving users and services only the permissions they actually need. It reduces the impact of **accidental actions or compromised accounts**.

* EC2 provides **on-demand virtual servers**, so you can quickly add or remove instances based on workload. This provides much greater **elasticity** than physical servers.

* S3 is **object storage**, where data is stored as objects with metadata and unique keys. Block storage divides data into fixed-size blocks and works like a traditional disk.

* A **subnet** is a logical section of a VPC's IP address range. Its configuration determines whether resources are **publicly accessible or isolated/private**.

* RDS handles tasks such as **backups, patching, monitoring, and maintenance**, reducing the operational work compared with managing a database server yourself.

* Security groups act as **virtual firewalls** that control inbound and outbound traffic. They are **stateful**, meaning return traffic for an allowed connection is automatically permitted.

* The AWS CLI is useful for **automation, scripting, repeatable deployments, and efficient resource management**. The Console is more convenient for **visual exploration and manual management**.
