### Task 3

Technical debt accumulates in monolithic systems when developers repeatedly choose **quick fixes, outdated libraries, workarounds, and tightly coupled designs** instead of refactoring. Over time, the codebase becomes harder to understand, test, maintain, and modify, making each new change more expensive and increasing the risk of further technical debt.

### Task 5 : Bug vs Code Smell

* **Bug:** A defect that causes the program to produce incorrect or unexpected behavior.
* **Code smell:** A sign of poor design or maintainability that may not cause incorrect behavior, but suggests the code should be improved.

### Task 6 : Duplicated Code

Duplicated code is harmful because the same logic must be updated in multiple places. This increases **maintenance effort**, creates inconsistencies, and makes bugs more likely when one copy is changed but another is forgotten.

### Task 7 : Feature Envy

**Feature Envy** occurs when a class or method uses the data and methods of another class more than its own. It indicates that the responsibility may be in the **wrong class**, violating good encapsulation and making the design more tightly coupled.

### Task 8 : Shotgun Surgery vs Divergent Change

* **Shotgun Surgery:** One change requires modifications in **many different classes or files**. This makes changes scattered and difficult to maintain.
* **Divergent Change:** One class is frequently changed for **many different reasons**. This means the class has too many responsibilities.

**In short:** Shotgun Surgery = *one change → many places*.
Divergent Change = *one class → many reasons to change*.

### Task 10

**Extract Method** improves readability by breaking a large or complex method into **smaller, focused methods**, each with a clear purpose.

For example:

```java
void processOrder(Order order) {
    validateOrder(order);
    calculateDiscount(order);
    updateInventory(order);
    sendConfirmation(order);
}
```

Instead of having all the logic inside `processOrder`, each responsibility is separated into a meaningful method.

**Benefits:**

* Makes code easier to understand.
* Reduces method complexity.
* Makes individual logic easier to test and reuse.
* Gives methods descriptive names that explain **what** the code does.

### 2. Money Value Object

```java
import java.math.BigDecimal;
import java.util.Objects;

public final class Money {
    private final BigDecimal amount;
    private final String currency;

    public Money(BigDecimal amount, String currency) {
        this.amount = amount;
        this.currency = currency;
    }

    public BigDecimal getAmount() {
        return amount;
    }

    public String getCurrency() {
        return currency;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Money)) return false;

        Money other = (Money) obj;

        return amount.compareTo(other.amount) == 0
                && currency.equals(other.currency);
    }

    @Override
    public int hashCode() {
        return Objects.hash(amount.stripTrailingZeros(), currency);
    }
}
```

# Task 18 — Aggregates, Entities & Value Objects

### 1. Order Aggregate

```java
import java.math.BigDecimal;

public class Order {
    private final long id;
    private final java.util.List<OrderLine> lines = new java.util.ArrayList<>();
    private Money total;

    public Order(long id) {
        this.id = id;
        this.total = new Money(BigDecimal.ZERO, "USD");
    }

    public void addLine(OrderLine line) {
        lines.add(line);
        recalculateTotal();
    }

    private void recalculateTotal() {
        BigDecimal totalAmount = BigDecimal.ZERO;

        for (OrderLine line : lines) {
            totalAmount = totalAmount.add(
                    line.getPrice().getAmount()
            );
        }

        total = new Money(totalAmount, "USD");
    }

    public Money getTotal() {
        return total;
    }
}
```

### 3. Anti-Corruption Layer

Suppose the **legacy system** uses this:

```java
public class LegacyCustomer {
    public String customer_no;
    public String customer_name;

    public LegacyCustomer(String customer_no,
                          String customer_name) {
        this.customer_no = customer_no;
        this.customer_name = customer_name;
    }
}
```

Modern system:

```java
public class CustomerDTO {
    private final String id;
    private final String name;

    public CustomerDTO(String id, String name) {
        this.id = id;
        this.name = name;
    }

    public String getId() {
        return id;
    }

    public String getName() {
        return name;
    }
}
```

ACL translates between them:

```java
public class CustomerACL {

    public CustomerDTO translate(
            LegacyCustomer legacyCustomer) {

        return new CustomerDTO(
                legacyCustomer.customer_no,
                legacyCustomer.customer_name
        );
    }
}
```

Usage:

```java
LegacyCustomer legacy =
        new LegacyCustomer("C101", "Alice");

CustomerACL acl = new CustomerACL();

CustomerDTO modern = acl.translate(legacy);

System.out.println(modern.getId());
System.out.println(modern.getName());
```
