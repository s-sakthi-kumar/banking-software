
### Task 1: What do you understand about integration testing?
While unit testing checks individual components separately, integration testing checks whether they communicate and interact correctly.

### Task 2: Where do you use it and when ?
You use integration testing when you need to verify that different parts of an application work correctly together.

It is commonly used:

* After individual modules have been unit tested.
* When connecting an application to a database.
* When communicating with APIs or external services.
* When testing interactions between different services/modules.
* Before system/end-to-end testing.

### Task 3: Can you write an integration test for your existing code ?

this is an example of an integration test 
This test checks the route `/users/1` which uses the controller and service which connects to the database.


```java
@SpringBootTest
@AutoConfigureMockMvc
class UserIntegrationTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    void shouldGetUser() throws Exception {

        mockMvc.perform(get("/users/1"))
               .andExpect(status().isOk());
    }
}
```

### Task 4: What are test containers?
Testcontainers is a Java library that allows us to run real dependencies, such as PostgreSQL, MySQL, Redis, or Kafka, inside Docker containers during testing.

For example, instead of connecting our Spring Boot tests to an existing PostgreSQL database, we can start a temporary PostgreSQL container specifically for the test.

### Task 5: When do we use ? and what is the need for test containers?
We use Testcontainers mainly for integration testing, especially when our application depends on external services such as databases.

The main need is to make tests closer to the real environment.



### Task 7: What is code coverage. 
Code coverage is a measurement of how much of our source code is executed while running our automated tests.

For example, suppose our application has 100 lines of code, and our tests execute 80 of those lines.

Then:

Code Coverage = 80%

There are different types of coverage:

Line coverage → How many lines were executed?
Branch coverage → How many if/else or decision paths were tested?
Method coverage → How many methods were called?

Tools such as JaCoCo are commonly used in Java projects to measure code coverage.

### Task 8: What's the need for Code Coverage?

Code coverage helps us understand which parts of our code are actually being tested.


### Task 10: What is Redux used for?

Redux is a state management library used to store and manage shared application state in one central place.
Different React components can access this shared state without having to pass data through many layers of components.

### Task 12: What is useSelector used for?

useSelector is a React-Redux hook used to read data from the Redux store.
