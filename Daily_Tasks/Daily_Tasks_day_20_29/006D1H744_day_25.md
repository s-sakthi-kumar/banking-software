### 1. 12-Factor App & Portability

The 12-Factor methodology keeps applications **portable and resilient** by separating configuration from code, managing dependencies explicitly, treating services as replaceable resources, and using stateless processes. This makes the application easier to deploy consistently across different cloud platforms.

### 2. Configuration & Dependencies

**Externalizing configuration** keeps environment-specific values such as database URLs, passwords, and API keys outside the code. Spring Boot profiles (`dev`, `prod`, etc.) help maintain **dev/prod parity** while using different configurations.

**Difference:**

* **Configuration:** Values that change between environments, such as URLs, ports, and secrets.
* **Dependencies:** Libraries/frameworks the application needs to run, which should be explicitly declared and versioned (e.g., in `pom.xml`).


## Task 2
### How does cloud-native design differ from traditional monolithic application design in terms of scalability and resilience?
It uses loosely coupled, independently scalable components, making applications more scalable and resilient than traditional monoliths.

### How does the 12-Factor methodology ensure portability across cloud platforms?
It separates application code from environment-specific configuration and dependencies, allowing the same application to run across different cloud platforms.

### Why is maintaining a single codebase with multiple deploys critical for consistency?
It ensures all deployments use the same source of truth, preventing inconsistencies between environments and versions.

### Why should configuration be externalized instead of hardcoded in the application?
It allows the same codebase to run in different environments by changing configuration without modifying the application code.

### What is the difference between readiness and liveness probes in Spring Boot Actuator?
Liveness probe: Checks whether the application is alive and functioning. If it fails, the container may be restarted.
Readiness probe: Checks whether the application is ready to receive traffic. If it fails, the application is temporarily removed from the load balancer but not restarted.

### Why should backing services (like databases or queues) be treated as attached resources?
Treating databases, queues, and other services as attached resources makes them replaceable and independent of the application code.

### Why is it important to separate build, release, and run stages in deployment pipelines?
Separating these stages creates reproducible builds and ensures that the exact tested release is what gets deployed.

### Why is statelessness essential for horizontal scaling in cloud-native systems?
Statelessness: It allows any instance to handle any request, making it easy to add or remove instances without losing user state.

### Why does the 12-Factor methodology recommend port binding for service exposure?

Port binding: It lets an application expose its service directly through a port, making it self-contained and independent of a separate web server.

### How does process concurrency differ from vertical scaling?
Process concurrency: It runs multiple processes concurrently to handle more workload, while vertical scaling increases the resources (CPU/RAM) of a single machine.

### Why should processes be disposable in cloud-native environments?
Disposability: Processes should start quickly and shut down safely so they can be replaced, restarted, or scaled without disrupting the system.

### Why is minimizing differences between development and production environments critical?
Dev/prod parity: Minimizing differences prevents environment-specific bugs and ensures code behaves consistently in production.

### Why should logs be treated as event streams rather than files?
Logs as event streams: Logs should be emitted as continuous streams so external systems can collect, process, store, and analyze them independently of the application.

### How do Spring Boot profiles help manage environment-specific configurations?
Spring Boot profiles: Profiles allow different configurations to be activated for environments such as development, testing, and production.
